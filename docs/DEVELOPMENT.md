# دليل بيئة التطوير

## البدء (مرة واحدة)

```bash
npm run setup        # يثبّت playwright + Chromium
```

> المتطلبات: Node 20 أو أحدث. لا توجد أي اعتماديات تشغيل — التطبيق Vanilla JS، و`playwright` أداة اختبار فقط.

## الأوامر اليومية

| الأمر | ما يفعله |
|---|---|
| `npm run dev` | خادم محلي على http://localhost:8080 بدون كاش (`-- 3000` لتغيير المنفذ، `--log` لعرض الطلبات) |
| `npm run dev:mobile` | نفس الخادم لكن متاح على الشبكة؛ افتح العنوان المطبوع من جوالك على نفس الـ Wi-Fi |
| `npm run check:static` | سريع (ثوانٍ، بلا متصفح): صياغة كل ملفات JS + فحص الاتساق (يشمل مطابقة قائمة الكاش للمولَّدة) |
| `npm run test:scripts` | اختبارات سكربتات الأدوات (`apply-update.sh` ومولّد الكاش) على مشروع مؤقت + remote حقيقي |
| `npm run gen:precache` | يولّد قائمة `PRECACHE_URLS` في `sw.js` من القرص (`check:precache` يفحص دون كتابة) |
| `npm run test:browser` | الاختبارات في Chromium + فتح كل الصفحات الـ28 + فحص الشاشات الضيقة (320/360px) لتجاوز الحدود |
| `npm run check` | الثلاثة معاً (ثابت + سكربتات + متصفح) — شغّله قبل كل commit |
| `npm run bump -- patch` | يرفع الإصدار في كل الأماكن (أو `3.4.0` / `minor` / `major`) |

خيارات `test:browser`: `-- --only=tests` أو `-- --only=pages` أو `-- --only=narrow` أو `-- --headed` (تشاهد المتصفح). عند الفشل تجد لقطات الشاشة ومخرجات الاختبارات في `test-results/`.

## ما الذي يفحصه `check:consistency`؟

- رقم الإصدار نفسه في `package.json` و`config.js` و`sw.js` و`README` وأول سطر في `CHANGELOG`.
- كل ملف في `src/` (غير الاختبارات) وكل ملف CSS مذكور في `PRECACHE_URLS` داخل `sw.js` — وإلا لن يعمل offline — وكل مسار مذكور موجود فعلاً، **والقائمة مطابقة حرفياً لناتج المولّد** (`npm run gen:precache` يصلحها).
- كل ملف `*.test.js` مستورد في `src/tests/index.js` (وإلا لن يُشغَّل أبداً).
- أيقونات `manifest.json` وروابط `index.html` موجودة، ولا توجد BOM أو علامات دمج Git.

## سير العمل لإصدار جديد

1. عدّل الكود، وأضف ملف اختبار `src/tests/modules/audit-XXXX.test.js` واستورده في `src/tests/index.js`.
2. ملف جديد؟ لا شيء تفعله: قائمة الكاش في `sw.js` **مولَّدة** — شغّل `npm run gen:precache` (وسكربت التطبيق `apply-update.sh` يفعلها تلقائياً).
3. `npm run bump -- patch` ثم اكتب ملاحظات الإصدار في `CHANGELOG.md`.
4. `npm run check` — يجب أن يمر كله.
5. ادفع إلى GitHub؛ الـ CI يعيد نفس الفحص ويرفع لقطات الشاشة إن فشل.

## تطبيق تحديث على الجوال (Termux) بأمر واحد

```bash
cd ~/jalabiya-v3
bash scripts/apply-update.sh ~/storage/downloads/jalabiya-patch-3.3.66.zip
```

يفك الـ zip ← ينسخه فوق المشروع ← يولّد قائمة الكاش ← يفحص الصياغة والاتساق ← يعرض الملفات المتغيرة ← `commit` (الرسالة من أحدث إدخال في `CHANGELOG.md` داخل التحديث) ← `push`.
**لو فشل أي فحص يتراجع عن كل شيء ولا يرفع.** يحتاج `git` و`unzip` و`tar` و`node` (`pkg install git unzip nodejs-lts`).

| خيار | معناه |
|---|---|
| `-m "رسالة"` | رسالة commit مخصّصة |
| `--dry-run` | يطبّق ويفحص ثم يتراجع (لمعاينة ما سيحدث) |
| `--no-push` | commit فقط |
| `--confirm` | يسأل قبل الـ commit |
| `--skip-checks` | بلا فحوص (للطوارئ فقط) |
| `--force` | يسمح بشجرة عمل غير نظيفة (يعطّل التراجع التلقائي) |

حذف ملفات: ضع في جذر التحديث ملف `DELETE.txt` بمسار في كل سطر (لا يُنسخ هو نفسه). رموز الخروج: `0` نجاح · `1` استخدام/بيئة · `2` شجرة غير نظيفة · `3` فشل فحص (تم التراجع) · `4` فشل push.

## ترحيل البيانات: نسخة لكل سجل

كل سجل يحمل `_v` (بلا `_v` = 1) ويُختم تلقائياً عند كل كتابة (`idb.put`). لإضافة حقل جديد لكل السجلات القديمة (مقاسات، رصيد…): أضف في `RECORD_MIGRATIONS` (`src/data/record-meta.js`):

```js
export const RECORD_MIGRATIONS = {
  customers: [
    { to: 2, up(rec) { rec.wallet = rec.wallet ?? 0; return rec; } },   // 2، 3، 4… بلا فجوات
  ],
};
```

- الدالة **idempotent ودفاعية** (قد يكون السجل من نسخة أقدم بكثير) ولا تغيّر `id/createdAt/updatedAt` (تُعاد تلقائياً).
- يُرحَّل كل سجل قديم عند أول فتح، وبعد كل مزامنة/استعادة/استيراد، **بعد نسخة احتياطية تلقائية** (إن فشلت لا يُرحَّل شيء).
- فشل ترحيل سجل لا يكتب نصفه: يبقى كما هو ويُعاد المحاولة لاحقاً. سجل بنسخة أحدث من المعروفة (من جهاز بتطبيق أحدث) لا يُلمس.
- لا يغيّر `updatedAt` فلا يطغى على تعديلات الأجهزة الأخرى.

## المزامنة: الدمج على مستوى الحقول

`idb.put` يسجّل وقت آخر تعديل لكل حقل (`_ft`، وأساسه `_fb`). عند «دمج» بيانات السحابة (`record-merge.js`):
- تعديل حقلين مختلفين على جهازين → يجتمعان في سجل واحد.
- الحقل نفسه على الجهازين بعد آخر مزامنة → يفوز الأحدث ويُسجَّل **تعارض** في صفحة المزامنة (القيمتان + زر «استرجاع القيمة الأخرى»).
- الدمج تبادلي (`merge(a,b) = merge(b,a)`) فيتقارب الجهازان. المصفوفات والكائنات المتداخلة قيمة واحدة للحقل، وحقول البنود والمجاميع في الطلب (`ATOMIC_GROUPS`) تُؤخذ معاً من طرف واحد.
- سجل بنسخة مخطط مختلفة (`_v`) لا يُدمج حقلاً حقلاً: الأحدث كاملاً ثم يتكفل الترحيل.
- ⚠️ سجل كتبه إصدار أقدم (بلا `_ft`) يُقارَن بزمن `updatedAt` لكل حقل (= سلوك «آخر حفظ يفوز» السابق) حتى يُعدَّل بالإصدار الجديد.

## زر «أبلغ عن مشكلة»

الإعدادات ← «🛟 الدعم وحل المشاكل»: يجمّع الإصدار والجهاز وحالة التخزين والمزامنة وآخر 15 خطأ في رسالة (مشاركة/نسخ/ملف). **أعداد فقط**: لا أسماء ولا هواتف ولا مبالغ، والأخطاء تُنقّى (`redactText`)، والمستخدم يراجع النص قبل الإرسال. المصدر: `src/services/diagnostics.js`.

## الـ CI (GitHub Actions)

`.github/workflows/check.yml` على كل push وPull Request: وظيفة **static** (صياغة + اتساق + قائمة الكاش + اختبارات السكربتات) ثم **browser** على منطقتين زمنيتين (`UTC` و`Africa/Cairo` — مصر تطبّق التوقيت الصيفي فتنكشف أخطاء حدود اليوم 23/25 ساعة)، ثم بوابة `ci-ok` ثابتة الاسم لحماية الفرع. لقطات الشاشة تُرفع عند الفشل.
